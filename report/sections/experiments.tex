\section{Experimental Setup}

\subsection{Dataset}

We use the CPJUMP1 pilot~\cite{chandrasekaran2024jump}, a public dataset from the JUMP Cell Painting Consortium hosted on the Cell Painting Gallery (S3 prefix \texttt{cpg0000-jump-pilot}). It has 51 plates and 3.31\,TiB of raw 16-bit TIFF images. The perturbations are 303 small-molecule compounds, 160 CRISPR knockouts and 176 ORF overexpressions, in two cell lines (U2OS and A549), mostly at two timepoints per modality. Each gene target is linked to at least two compounds, which is what makes compound--gene matching testable. Each plate has 384 wells with 7 to 16 imaged sites per well, and each site has five fluorescence channels at $1080 \times 1080$ pixels plus three brightfield channels that we do not use.

\subsection{Data Pipeline}

The raw plates are 58 to 118\,GiB each, so we stream, encode and delete. Each plate is downloaded to scratch, passed once through the frozen DINOv3 backbone, and removed once the per-channel CLS tokens are on disk. The resulting channel-token cache is read by every training run. Text embeddings are cached the same way: each prompt is encoded once by the frozen ModernBERT and the 768-d CLS token stored.

\subsection{Splits}

Wells are split by perturbation. Each \texttt{broad\_sample} is hashed with a fixed seed into train, validation or test at 80/10/10, so all replicate wells of a perturbation land in one split and every split contains all three modalities. Control wells are excluded from training and evaluation. The validation split has 2,220 wells from 98 perturbations (42 compound, 34 CRISPR, 22 ORF), about 24 replicate wells each. The test split has 1,860 wells from 86 perturbations. The hash is deliberately stable: changing it would move every well to a different split and invalidate every split saved on disk.

\subsection{Retrieval Protocol}
\label{sec:protocol}

Replicate wells share one text vector, so the text side of a split has $P$ distinct vectors (98 on validation) and the image side has $N$ wells (2,220). We report four directions, each with an analytic random baseline computed from the same $P$ and $N$.

\begin{itemize}
    \item \textbf{Well-level image-to-text.} Each of the $N$ wells ranks the $P$ unique texts. One candidate is correct. Random Recall@$k$ is $k/P$.
    \item \textbf{Well-level text-to-image.} Each of the $P$ texts ranks all $N$ wells and is scored on the rank of its first correct replicate. With $m$ replicate wells among $N$ candidates, random Recall@$k$ is $1 - \binom{N-m}{k} / \binom{N}{k}$.
    \item \textbf{Perturbation-level, both directions.} The well embeddings of each perturbation are averaged and re-normalized into one profile, and the $P$ profiles are ranked against the $P$ texts. This is the unit of the standard CPJUMP1 protocol. Random Recall@$k$ is $k/P$.
\end{itemize}
We report Recall@\{1, 5, 10\} and the median rank of the first correct match. Model selection uses the validation text loss, and we report both the validation and the test split.

An earlier version of this evaluation ranked each well against all $N$ well-texts instead of the $P$ unique texts. Because the pool then held about 24 exact copies of every text vector, a model that scores identical vectors identically placed all copies at consecutive ranks, which capped Recall@5 and Recall@10 near Recall@1 and made image-to-text retrieval look worse than a shuffled baseline that interleaved the copies. Section~\ref{sec:pitfall} gives the arithmetic. Every current retrieval result uses the unique-text pool.

\subsection{Standard CPJUMP1 Benchmark}

We also run the benchmark of Chandrasekaran et al.~\cite{chandrasekaran2024jump} on exported well embeddings, with the pinned copairs implementation the reference code uses. Trained checkpoints encode every well of a plate (controls included) in fp32, subtract the plate's negative-control mean, and write one profile CSV per plate in the layout the benchmark reads. The benchmark covers the 40 plates at standard seeding density without antibiotics, at two timepoints per modality (short: compound 24\,h, ORF 48\,h, CRISPR 96\,h; long: 48\,h, 96\,h, 144\,h). It measures three things with average precision (AP) against a permutation null: \emph{replicability}, whether replicate wells of one perturbation retrieve each other; \emph{target matching}, whether perturbations of one modality that share a target retrieve each other; and \emph{gene--compound matching}, whether compounds retrieve the CRISPR or ORF perturbations of their target. Each track reports mean AP (mAP) and the fraction of perturbations whose AP passes $q < 0.05$ (fraction retrieved). Summary fractions are unweighted means over tracks; summary mAP values pool the scored rows and are therefore weighted by track size.

One caveat applies to every fraction-retrieved value in this paper and in the reference results: the permutation null is random, so the set of perturbations that pass the threshold changes from run to run of identical code. Only replicability mAP is deterministic. Small differences in fraction retrieved should not be read as effects.

\subsection{Baselines}

\begin{itemize}
    \item \textbf{CellProfiler}~\cite{carpenter2006cellprofiler}. Handcrafted features. On CPJUMP1 target matching, the published fraction retrieved is 4.3 to 25.1\%~\cite{chandrasekaran2024jump}. We did not rerun the CellProfiler pipeline.
    \item \textbf{CellCLIP}~\cite{lu2025cellclip}. We quote the published Bray-dataset retrieval (best Recall@10 7.4\%) and CORUM recall (0.354). We also ran the released CellCLIP checkpoint through our benchmark harness on the short timeline, exporting profiles with CellCLIP's own encoder path. Those numbers are the closest like-for-like comparison we have, with two caveats noted where they appear: CellCLIP's evaluation recipe includes a control-fitted KernelPCA batch correction that our export does not apply, and the two are separate runs of a non-deterministic harness.
    \item \textbf{CWA-MSN}~\cite{huang2025cwamsn}. CORUM gene--gene recall 0.386 with 22M parameters. Its benchmarks (CORUM, HuMAP, Reactome) are not among ours, so no comparable number exists.
\end{itemize}

\subsection{Ablation Design}
\label{sec:ablation_design}

The base model was trained with binary CWCL labels, uniform random batches, no replicate term and no plate offsets, on the 100-epoch schedule. The ablations share one config that differs from the base in three ways: perturbation-aware batches, a 30-epoch schedule and early stopping (patience 8). From that shared control we change one thing at a time: gene-aware soft labels ($\alpha = 0.6$), the replicate alignment loss ($\lambda_{\text{rep}} = 0.3$), and plate offsets. The plate-offset variant was run three times: once with the earlier in-batch mean subtraction, once with condition-relative offsets for the 40 plates the reference metadata covers and a zero offset for the other 11, and once with offsets for all 51 plates. A final run turns all three additions on together. Every run uses seed 42, batch size 256 and the same split. All retrieval numbers below therefore come from one seed. At 98 validation candidates one retrieved perturbation changes recall by 1.02 percentage points; at 86 test candidates it changes recall by 1.16 points. Differences of a few points are therefore only a few perturbations and are not treated as effects without repeated seeds.

\subsection{Implementation}

Everything runs on one RTX 5080 (16\,GB). AdamW, learning rate $10^{-4}$, weight decay 0.2, 100 warm-up steps then cosine decay, FP16, gradient clipping at 1.0. CCF: one layer, four heads. Projection heads: hidden width 512, dropout 0.3. The code, configs and split manifests are released with the paper.
